# 视觉目标管理与跟踪系统

1. 我干了啥
这次大作业我用 C++ 实现了一个目标跟踪器,就是摄像头每传来一帧数据，我把里面的目标识别出来，给新目标建档，给老目标更新位置和速度。如果目标几帧没出现，就判定它“丢失”，如果它后来又出现了，就让它“复活”。

2. 代码里的四大核心模块
我按照面向对象的思想，把这个系统拆成了四个类：
*   **`TrackingBase`（跟踪基类）**：这是所有装甲的“户口本”。我把大家共有的属性（编号、坐标、速度、状态）都放在这里。另外，为了安全，我写了一个 `getSnapshot()` 专门用来给外界发数据，保证外界不能随便改我的内部状态。
*   **`ArmorTarget`（普通装甲）**：继承了基类。它的特点是“命短”，连续 3 帧没看到它，我就得把它标记为 `LOST`。
*   **`SpinningTarget`（旋转装甲）**：也继承了基类，但它多了一个“转圈”的特异功能（角度和角速度）。而且它比较难杀，得连续 5 帧没看到才算死。
*   **`TargetManager`（目标管理器）**：这是最重要的“保安队长”。它负责检查进来的帧合不合法（比如帧号倒退、ID 重复、负数 ID），然后去更新老目标或者创建新目标，最后把这一帧所有目标的快照打包成 `Result` 交差。

3. 踩过的坑和解决思路
*   **坑 1：多态带来的内存泄漏**。一开始我不懂为什么基类要写一个 `virtual ~TrackingBase() = default;`。后来明白了，如果不加 `virtual`，用基类指针删子类对象时，子类特有的数据就清理不干净。加上它，就安全了。
*   **坑 2：目标死没死，到底怎么判？** 刚开始我总是把状态（TRACK/LOST）和类型（普通/旋转）搞混。后来在统计循环里，我用 `getStatus()` 判断它是不是活着，用 `getType()` 判断它是普通还是旋转，这才把丢失阈值（3帧和5帧）写对。
*   **坑 3：为啥交报告要给快照？** 因为外部系统拿到目标指针可能会乱改数据。所以我在 `getSnapshot` 里把当前数据复印了一份交出去。这样就算外面把复印件撕了，我底层的原件也绝对安全。
